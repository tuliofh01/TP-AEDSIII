================================================================================
                         1. INTRODUCAO AO CMAKE
================================================================================

CMake (Cross-Platform Make) e um sistema de build de codigo aberto e 
multi-plataforma. Ele gerencia o processo de build de maneira 
independente do compilador, produzindo arquivos de build nativos 
(Makefiles, arquivos Ninja, projetos Visual Studio, etc.) para diferentes 
plataformas.

Caracteristicas Principais:
- Multi-plataforma: Funciona em Linux, macOS, Windows
- Independente de linguagem: Principalmente usado para C/C++ mas suporta outras
- Baseado em geradores: Cria arquivos de build para multiplos sistemas
- Modular: Suporta find_package, FetchContent e modulos personalizados

================================================================================
                2. POR QUE O CMAKE E ESSENCIAL PARA PROJETOS C++ MODERNOS
================================================================================

2.1 GERENCIAMENTO COMPLEXO DE DEPENDENCIAS
------------------------------------------
Projetos C++ modernos frequentemente dependem de multiplas bibliotecas 
externas. O CMake simplifica isso atraves de:

    +------------------+     +-------------------+     +------------------+
    |   Seu Projeto    | --> |    Build CMake    | --> |   Executavel    |
    +------------------+     +-------------------+     +------------------+
                                  |         |
                    +-------------+---------+
                    |             |             |
              +-----v----+   +-----v----+   +-----v----+
              | hello_   |   |   Lua    |   |  luaaa   |
              | imgui    |   |  library |   |  library |
              +----------+   +----------+   +----------+

2.2 COMPATIBILIDADE MULTI-PLATAFORMA
------------------------------------
O mesmo CMakeLists.txt funciona em diferentes plataformas:

    Plataforma    | Gerador           | Compilador
    --------------|-------------------|------------------
    Linux         | Ninja/Unix Makefiles    | GCC/Clang
    macOS         | Ninja/Xcode        | Clang
    Windows       | Ninja/Visual Studio     | MSVC/MinGW

2.3 BUSCA DE DEPENDENCIAS (FetchContent)
----------------------------------------
CMake pode automaticamente baixar e compilar dependencias:

    FetchContent_Declare(hello_imgui
        GIT_REPOSITORY https://github.com/pthom/hello_imgui.git
        GIT_TAG        master
        SOURCE_DIR    "${LOCAL_LIBS_DIR}/hello_imgui"
    )
    FetchContent_MakeAvailable(hello_imgui)

Isso elimina a necessidade de instalacao manual de bibliotecas.

================================================================================
                   3. ANALISE ESTRUTURAL DO CMAKELISTS.TXT
================================================================================

3.1 CABECALHO DO ARQUIVO E VERSAO MINIMA
-----------------------------------------
    cmake_minimum_required(VERSION 3.20)
    
    project(TP_AEDSIII LANGUAGES CXX C)
    set(CMAKE_CXX_STANDARD 20)
    set(CMAKE_CXX_STANDARD_REQUIRED ON)

Explicacao:
- cmake_minimum_required(VERSION 3.20): Define a versao minima do CMake
- project(TP_AEDSIII LANGUAGES CXX C): Define o nome do projeto e linguagens
  - LANGUAGES CXX C: Ativa compiladores C++ e C
- set(CMAKE_CXX_STANDARD 20): Solicita o padrao C++20
- set(CMAKE_CXX_STANDARD_REQUIRED ON): Torna C++20 obrigatorio

3.2 FETCHCONTENT - GERENCIAMENTO DE DEPENDENCIAS
-------------------------------------------------
    include(FetchContent)
    
    set(LOCAL_LIBS_DIR "${CMAKE_SOURCE_DIR}/libs")
    
    FetchContent_Declare(hello_imgui
        GIT_REPOSITORY https://github.com/pthom/hello_imgui.git
        GIT_TAG        master
        SOURCE_DIR    "${LOCAL_LIBS_DIR}/hello_imgui"
    )
    FetchContent_MakeAvailable(hello_imgui)

Explicacao:
- include(FetchContent): Ativa o modulo FetchContent
- FetchContent_Declare(): Declara projeto externo
  - GIT_REPOSITORY: URL do repositorio Git
  - GIT_TAG: Versao/branch para fazer checkout
  - SOURCE_DIR: Onde armazenar o codigo baixado
- FetchContent_MakeAvailable(): Baixa e configura a dependencia

Bibliotecas baixadas neste projeto:
  +------------+------------------------------------------+
  | Biblioteca | Proposito                                |
  +------------+------------------------------------------+
  | hello_imgui| Framework GUI com integracao ImGui       |
  | lua        | Nucleo da linguagem de script Lua        |
  | luaaa      | Biblioteca de ligacao C++ para Lua       |
  +------------+------------------------------------------+

3.3 DETECCAO DE PLATAFORMA
--------------------------
    if(NOT CMAKE_GENERATOR)
        if(WIN32)
            set(CMAKE_GENERATOR "Ninja" CACHE STRING "Generator" FORCE)
            set(USE_MINGW ON)
        elseif(APPLE)
            set(CMAKE_GENERATOR "Ninja" CACHE STRING "Generator" FORCE)
        elseif(UNIX)
            set(CMAKE_GENERATOR "Ninja" CACHE STRING "Generator" FORCE)
        endif()
    endif()

Explicacao:
- Detecta o sistema operacional e define o gerador padrao
- CMAKE_GENERATOR: O sistema de build a usar (Ninja, Make, Visual Studio)
- Usa Ninja para builds mais rapidos em todas as plataformas

3.4 BACKEND ESPECIFICO DA PLATAFORMA
------------------------------------
    if(WIN32)
        find_package(OpenGL REQUIRED)
        set(PLATFORM_LIBS OpenGL::GL)
    elseif(APPLE)
        find_package(OpenGL REQUIRED)
        set(PLATFORM_LIBS OpenGL::GL)
    elseif(UNIX)
        find_package(OpenGL REQUIRED)
        set(PLATFORM_LIBS OpenGL::GL)
    endif()

Explicacao:
- find_package(OpenGL REQUIRED): Procura pela biblioteca OpenGL
- PLATFORM_LIBS: Armazena bibliotecas especificas da plataforma para linkar
- Usando OpenGL para renderizacao grafica em todas as plataformas

3.5 FUNCOES CMAKE DO HELLO_IMGUI
---------------------------------
    set(HELLO_IMGUI_CMAKE_PATH "${CMAKE_SOURCE_DIR}/libs/hello_imgui/hello_imgui_cmake")
    include(${HELLO_IMGUI_CMAKE_PATH}/hello_imgui_add_app.cmake)
    include(${HELLO_IMGUI_CMAKE_PATH}/hello_imgui_build_lib.cmake)

Explicacao:
- Inclui funcoes CMake personalizadas da biblioteca hello_imgui
- hello_imgui_add_app(): Auxiliar para criar aplicacoes GUI
- Isso simplifica a criacao de aplicacoes baseadas em ImGui

3.6 CRICACAO DE DIRETORIOS
---------------------------
    file(MAKE_DIRECTORY ${CMAKE_SOURCE_DIR}/data)
    file(MAKE_DIRECTORY ${CMAKE_SOURCE_DIR}/src/views)

Explicacao:
- Cria os diretorios necessarios antes do build
- Garante que os diretorios data/ e src/views/ existam

3.7 CONFIGURACAO DO DIRETORIO DE SAIDA
---------------------------------------
    set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_SOURCE_DIR}/builds)

Explicacao:
- Define onde os executaveis compilados serao放置
- Neste projeto: diretorio /builds/

3.8 BUSCA AUTOMATICA DE ARQUIVOS DE FONTE
------------------------------------------
    file(GLOB_RECURSE APP_SOURCES 
        "${CMAKE_SOURCE_DIR}/src/*.cpp"
    )

Explicacao:
- Automaticamente encontra todos os arquivos .cpp no diretorio src/
- GLOB_RECURSE: Busca recursivamente em subdiretorios
- Elimina a necessidade de adicionar arquivos manualmente ao CMakeLists.txt

Beneficios:
  - Novos arquivos adicionados a src/ sao automaticamente compilados
  - Nao requer atualizacoes manuais no CMakeLists.txt
  - Reduz erros humanos

3.9 CRICACAO DO EXECUTAVEL
--------------------------
    hello_imgui_add_app(TP_AEDSIII ${APP_SOURCES})

Explicacao:
- Cria o executavel principal usando o auxiliar hello_imgui
- TP_AEDSIII: Nome do executavel
- ${APP_SOURCES}: Todos os arquivos de fonte coletados

3.10 DIRETORIOS DE INCLUSAO
---------------------------
    target_include_directories(TP_AEDSIII PRIVATE
        ${CMAKE_SOURCE_DIR}/src
        ${CMAKE_SOURCE_DIR}/libs/luaaa
        ${CMAKE_SOURCE_DIR}/libs/lua/src
        ${CMAKE_SOURCE_DIR}/libs/hello_imgui/src
    )

Explicacao:
- Adiciona diretorios onde o compilador procura arquivos de cabeçalho
- PRIVATE: Estas inclusoes sao apenas para este alvo, nao para dependentes
- Permite que #include encontre cabecalhos nesses diretorios

3.11 LINKANDO BIBLIOTECAS
-------------------------
    target_link_libraries(TP_AEDSIII PRIVATE
        lua
        hello-imgui::hello_imgui
        ${PLATFORM_LIBS}
    )

Explicacao:
- Liga bibliotecas ao executavel
- lua: Biblioteca Lua do FetchContent
- hello-imgui::hello_imgui: Framework GUI
- ${PLATFORM_LIBS}: OpenGL e outras libs da plataforma

3.12 FLAGS DO COMPILADOR
-------------------------
    if(CMAKE_CXX_COMPILER_ID STREQUAL "GNU" OR CMAKE_CXX_COMPILER_ID STREQUAL "Clang")
        add_compile_options(-Wall -Wextra -Wpedantic)
    elseif(CMAKE_CXX_COMPILER_ID STREQUAL "MSVC")
        add_compile_options(/W4 /permissive-)
    endif()

Explicacao:
- Adiciona flags de aviso especificas do compilador
- -Wall -Wextra -Wpedantic: Avisos abrangentes para GCC/Clang
- /W4 /permissive-: Conformidade estricta com padroes MSVC

================================================================================
                4. CONCEITOS CHAVE DO CMAKE USADOS NESTE PROJETO
================================================================================

4.1 ALVOS (TARGETS)
-------------------
Um alvo representa um artefato de build (executavel ou biblioteca).

    Tipos usados neste projeto:
    +-----------------+-------------------------------------------+
    | Tipo de Alvo   | Descricao                                 |
    +-----------------+-------------------------------------------+
    | executavel      | TP_AEDSIII, run_tests                     |
    | biblioteca stat | imgui, hello_imgui (interna)              |
    | biblioteca obj  | lua                                       |
    +-----------------+-------------------------------------------+

4.2 PROPRIEDADES
-----------------
Alvos tem propriedades que configuram como sao construidos:

    - SOURCES: Arquivos de fonte para compilar
    - INCLUDE_DIRECTORIES: Caminhos de busca de cabecalho
    - COMPILE_OPTIONS: Flags do compilador
    - LINK_LIBRARIES: Bibliotecas para linkar

4.3 ESPECIFICADORES DE ACESSO
------------------------------
    target_link_libraries(TP_AEDSIII PRIVATE lua)

    +----------+---------------------------------------------------+
    | Specifier| Descricao                                        |
    +----------+---------------------------------------------------+
    | PUBLIC   | Propaga para dependentes                          |
    | PRIVATE  | Usado apenas por este alvo                        |
    | INTERFACE| Apenas necessario por dependentes                 |
    +----------+---------------------------------------------------+

4.4 VARIAVEIS
-------------
CMake usa variaveis extensivamente:

    Definidas pelo projeto:
    - APP_SOURCES: Arquivos de fonte para aplicacao principal
    - LOCAL_LIBS_DIR: Localizacao das bibliotecas baixadas
    - PLATFORM_LIBS: Bibliotecas especificas da plataforma

    Definidas pelo CMake:
    - CMAKE_SOURCE_DIR: Diretorio raiz do projeto
    - CMAKE_BINARY_DIR: Diretorio de build
    - CMAKE_CXX_STANDARD: Versao do padrao C++

4.5 EXPRESSOES DE GERADOR
-------------------------
Usado para configuracoes condicionais baseadas no tipo de build:

    $<BUILD_INTERFACE:...>  - Para construir
    $<INSTALL_INTERFACE:...> - Para instalacao
    $<BOOL:...>           - Operacoes booleanas

================================================================================
                     5. EXPLICACAO DO PROCESSO DE BUILD
================================================================================

5.1 FASE DE CONFIGURACAO
-------------------------
    cmake -G Ninja -S . -B cmake-build-release_build

    Passo a passo:
    1. CMake le o CMakeLists.txt
    2. Processa FetchContent (baixa dependencias)
    3. Gera regras de build (arquivos Ninja)
    4. Saida para cmake-build-release_build/

5.2 FASE DE BUILD
-----------------
    cmake --build cmake-build-release_build

    Passo a passo:
    1. Ninja le os arquivos de build gerados
    2. Compila arquivos de fonte (.cpp -> .o)
    3. Linka arquivos objeto com bibliotecas
    4. Produz executavel no diretorio builds/

5.3 EXECUCAO
------------
    ./builds/TP_AEDSIII

    O executavel:
    1. Inicializa estado Lua
    2. Carrega ligacoes ImGui personalizadas
    3. Cria DataManager para Lua
    4. Executa HelloImGui com UI definida em Lua
